# 精确最优基准：给启发式算法一把"尺子"

现有实验的比较对象只有 `all-end / all-edge / all-cloud` 三个朴素策略和 A–E 五种算法。
它们彼此之间的胜负能说明"谁更好"，却回答不了两个关键问题：

1. 最好的算法离**理论最优**还有多远？
2. 某个算法输，是因为策略差，还是因为这个加权目标本身就无法用单目标启发式做好？

本模块用**穷举**给出 n ≤ 12 时的精确最优解与完整 Pareto 前沿，作为一把独立的尺子。
它不参与"五种算法"的排序，也不改动 `dag_simulator.py` 和任何 `algo_[a-e]_*.py`。

## 1. 最优是怎么定义的

对固定的 DAG，`simulate(dag, decision)` 是确定性的：给定每个任务的落层
`decision[i] ∈ {end, edge, cloud}`，完成时间 `makespan` 与手机能耗 `energy` 就唯一确定。
因此 n 个任务只有 `3^n` 种决策，n ≤ 12 时最多 531 441 种，可以全部枚举。

- **加权目标**：`f = makespan + λ · energy`，默认 `λ = 0.5`（与报告 5.3 节口径一致）。
- **精确最优**：`argmin f`，即 `objective` 最小；若并列取 makespan 更小者。
- **Pareto 前沿**：所有不被支配的 `(makespan, energy)` 点，按 makespan 升序、energy 严格降序。
  前沿左端是"理论最快"，右端是"理论最省电"，加权最优通常落在两端之间。

注意：精确最优是**在仿真器模型内**的最优，不是物理世界的最优；它的意义是消除
"算法之间互相比较"的相对性，给出一致的绝对坐标。

## 2. 实现

`algo_f_exact.py`：

| 函数 | 作用 |
|---|---|
| `objective(makespan, energy, lam=0.5)` | 加权目标 |
| `evaluate(dag, decision)` | 与 `simulate()` 等价的快速打分（单次 O(n)，不建 timeline） |
| `exact_front(dag, lam=0.5)` | 枚举全部 `3^n` 个决策，返回非支配前沿（含决策与逐层任务数） |
| `exact_opt(dag, lam=0.5)` | 前沿上 `f` 最小的点，附 `front_size`、`points` 等元信息 |
| `is_dominated(...)` / `on_front(...)` | 支配关系与"是否落在前沿上"的判定 |

`evaluate()` 按 `topo_order(dag, priority=rank_upward(dag))` 逐行复刻 `simulate()` 的
输入上传、前驱传输、层排队、出口回传与能耗公式；`exact_front()` 对每个组合调用它，
按 `(makespan, energy)` 排序后一遍扫描即可得到前沿（O(P log P)，P = 3^n）。

**规模上限**：`MAX_EXACT_N = 12`。n = 13 时 3^13 ≈ 159 万，单实例就要数十秒，
而且内存与 CSV 都会明显膨胀，因此超过 12 直接抛 `ValueError`，提示改用启发式或缩小 n。

## 3. 正确性怎么保证

`verify_exact.py` 用 5 组断言把"精确"二字钉死（可重复运行）：

1. **与仿真器对拍**：n = 5/8/13/20/30 共 60 个随机实例、随机决策，`evaluate()` 与
   `simulate()` 的 makespan/energy 逐点一致；
2. **前沿性质**：n = 5/7 各 3 个 seed，前沿内部互不支配、按 makespan 正确排序，
   且随机抽 400 个决策都能在前沿中找到支配它的点（无遗漏）；
3. **暴力枚举交叉验证**：n = 4/5/6 各 4 个 seed，`exact_opt()` 的目标值与
   直接 `simulate()` 扫描全部 `3^n` 个决策得到的最小值一致（容差 1e-6）；
4. **决策可回放**：n = 9 时把前沿上每个点的决策交回 `simulate()`，目标值一致；
5. **上限保护**：n = 13 必须被拒绝。

```bash
python verify_exact.py     # 全部 PASS
```

## 4. 实验设置

`experiments/optimality_gap.py`：

- 规模与样本：`n = 8`（10 seeds）、`n = 10`（10 seeds）、`n = 12`（5 seeds）；
  n 越大枚举越贵，故 n = 12 减半；
- DAG：`gen_dag(n, p_edge=0.15, seed=...)`，比默认 0.3 更稀疏，避免小图退化成"全在端"；
- 参与对比：all-end / all-edge / all-cloud、A 随机、B 贪心、C HEFT、
  E-HEFT（α = 0.25/0.5/0.75/1.0）；装 torch 时自动追加 D-DQN；
- 指标：`gap% = 100 × (f_alg / f_opt − 1)`，越小越好；`ms_ratio_min`、`en_ratio_min`
  分别是相对"理论最快 makespan"和"理论最低能耗"的倍数；
- 汇总：每个 n × 算法给出 mean / median / p90 / max gap，另加两行**事后参照**：
  `oracle-best-single`（逐实例挑最好的算法）与 `oracle-best-eheft-alpha`（逐实例挑最好的 α）。

全量运行约 33 秒，枚举 331 万个决策。`--quick` 只跑 n = 8、3 seeds，用于冒烟。

## 5. 结果

### 5.1 n = 10 主表（10 seeds）

| 算法 | 平均 gap | 中位 gap | 最大 gap | makespan / 理论最快 | 能耗 / 理论最低 |
|---|---:|---:|---:|---:|---:|
| E-HEFT α=0.75 | 28.1% | 6.6% | 81.4% | 1.214 | 1.654 |
| C HEFT | 30.0% | 5.9% | 81.4% | 1.185 | 1.782 |
| D DQN | 30.8% | 25.7% | 56.5% | 1.451 | 1.199 |
| B 贪心 | 35.2% | 21.7% | 83.6% | 1.350 | 1.607 |
| E-HEFT α=0.5 | 38.7% | 41.9% | 84.9% | 1.318 | 1.787 |
| 全在边 | 39.8% | 39.7% | 56.5% | 1.650 | 1.059 |
| 全在云 | 68.1% | 65.9% | 97.9% | 1.523 | 2.343 |
| 全在端 | 446.3% | 466.0% | 572.8% | 5.872 | 5.510 |
| 参照：逐实例选最优算法 | 12.5% | 5.9% | 45.6% | — | — |
| 参照：逐实例选最优 α | 26.7% | 5.9% | 77.2% | — | — |

（E-HEFT α=1.0 的每一行都与 C HEFT 完全相同，验证了"α=1 严格等价 HEFT"的设计声明；
因此上表不再单列。α=0.25 平均 gap 44.4%，劣于 α=0.5，更劣于 α=0.75。）

### 5.2 跨规模：平均 gap 与"专精"程度

| n（seeds） | HEFT | DQN | E-HEFT α=0.75 | 逐实例最优参照 |
|---|---:|---:|---:|---:|
| 8（10） | 15.1% | 25.3% | 23.2% | 7.7% |
| 10（10） | 30.0% | 30.8% | 28.1% | 12.5% |
| 12（5） | 20.7% | 51.3% | 42.1% | 15.0% |

### 5.3 三个可以直接写进结论的观察

**① 连"逐实例挑最好算法"都离最优 8–15%。**
这不是某个算法没调好，而是所有候选算法都带单目标偏置：HEFT 只看完成时间，
全在边只看能耗，DQN 在 13 维状态上学到的是粗粒度策略。加权目标的最优点通常
既不在"全在边"也不在"全在云"，而在两者之间（案例见 5.4），靠单目标算法无法逼近。

**② HEFT 是"时延专精"，不是加权目标的标杆。**
它的 makespan 只比理论最快慢 10–18%，但能耗是最低能耗的 1.4–1.8 倍；
在 λ=0.5 下平均 gap 15–30%。中位数（6–11%）远小于均值，说明多数实例接近最优，
少数实例被"把任务放到端上执行"拖垮——端上执行 1 秒的能耗是云/边的数十倍。
因此"HEFT 是质量标杆"只在 makespan 这一维成立；报告比较加权目标时应写清口径。

**③ E-HEFT 的 α 应调到 0.75。**
α=0.5 是报告主推值，但在 n=8/10 上其平均 gap（30.5% / 38.7%）反而大于 α=0.75
（23.2% / 28.1%）；α=1.0 完全退化为 HEFT。α 越大越偏向时延，λ=0.5 的加权目标
恰好需要偏时延一侧的折中。n=12 上两者接近（41.9% vs 42.1%），说明最优 α 随规模漂移，
但 0.75 是比 0.5 更稳的默认值。

**④ DQN 在小图上没有优势，但"能耗观"比 HEFT 好。**
DQN 平均 gap（25–51%）不优于 HEFT，且 n=12 明显恶化；但它的能耗比（1.20）优于 HEFT（1.78），
在案例中甚至与"全在边"完全重合。可解释为：DQN 学会了"别把任务放端上"，
但没有学会在边/云之间做细粒度权衡。这与报告"DQN 泛化不足、小规模不占优"的结论一致，
本基准只是把它从定性说法变成了可量化差距。

### 5.4 案例：n = 10, seed = 9（HEFT 最差实例）

真实前沿只有 4 个点：

| makespan (s) | energy (J) | f (λ=0.5) | 端/边/云 |
|---:|---:|---:|---|
| 2.1893 | 2.0602 | **3.2194** | 0 / 4 / 6 |
| 2.3286 | 1.9849 | 4.3211 | 0 / 6 / 4 |
| 2.3510 | 1.8892 | 4.2956 | 0 / 6 / 4 |
| 2.5906 | 1.8239 | 3.5026 | 0 / 7 / 3 |

精确最优在左上端：2.19 s、2.06 J，**没有任何任务放在端上**。
C HEFT 给出 3.34 s / 5.00 J（f = 5.84，gap 81.4%），因为它把 2 个任务排到端上执行，
makespan 只多了 52%，能耗却多了 143%。反过来，"全在边"是 3.17 s / 1.88 J（gap 27.7%），
能耗接近最低，但完成时间比最优慢 45%。两者各占一个端点，加权最优在中间——
这正是单目标启发式无法覆盖的区域。

## 6. 局限

- 只覆盖 n ≤ 12。结论不能直接外推到 n = 20/50/100；它的用途是"检验启发式的偏置方向"，
  而不是替代大规模矩阵实验。
- λ 固定为 0.5。改 `LAM` 常量可换口径，但本模块没有做 λ 扫描（会成倍增加枚举后的汇总工作）。
- 精确性依赖仿真器语义。`dag_simulator.py` 一旦改动，必须重跑 `verify_exact.py`；
  本模块刻意不 import 仿真器内部函数，只调用公开的 `gen_dag / topo_order / rank_upward / simulate`。
- 枚举是"暴力 + 一次扫描"，不是分支定界；n = 12 的 33 秒可接受，n = 15 则不可行。

## 7. 复现

```bash
# 1. 自检（必须先 PASS）
python verify_exact.py

# 2. 全量：约 33 s，生成本目录下 4 个 CSV
python experiments/optimality_gap.py
python experiments/optimality_gap.py --quick   # n=8, 3 seeds 冒烟

# 3. 出图（图 11）
python experiments/plot_optimality.py
```

产物：

| 文件 | 内容 |
|---|---|

其他同学约定的步骤数与耗时。需要时单独执行上面三条命令即可（总耗时 < 1 分钟）。
