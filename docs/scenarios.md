# DAG 任务卸载与调度的实际应用场景调研（课题要求 3）

> 本文档回答要求 3：调研 DAG 任务卸载与调度在实际系统中的应用场景，分析不同应用场景下的任务特点及其对卸载算法的需求。
> 每个场景按"任务 DAG 形状 → 约束 → 对卸载算法的需求 → 本课题算法的适配性"四段展开。

## 场景 1：实时视频分析 / 智能监控

**典型 DAG**：视频帧 → 解码 → 目标检测 → 多目标跟踪 → 行为识别 → 告警/存储。
深层链式结构为主（6~10 层流水线），相邻任务间传输的是中间帧/特征图（数百 KB ~ 数 MB），前段（解码/检测）计算量大，后段（跟踪/逻辑）计算量小——是典型的"深而窄"DAG。

**任务特点与约束**：
- 时延敏感：监控告警要求秒级内响应，流水线时延直接决定告警实时性
- 数据量大：原始帧在端上产生，上传原始视频带宽开销巨大
- 隐私与合规：原始视频涉及隐私法规，倾向于在端/边就近处理，仅上传结构化结果

**对卸载算法的需求**：需要考虑**通信代价与计算代价的平衡**（本课题实验已证明：带宽受限时盲目录载到云端反而更慢）；前段重任务卸到边/云、后段轻任务留在端上是典型最优形态。

**本课题算法适配**：C-HEFT/E-HEFT 最匹配——DAG 结构固定且环境静态，HEFT 的关键路径优先 + 最早完成时间策略正为此类流水线设计；隐私偏好可通过在 E-HEFT 中给"端"层的能耗代价加权来体现。

## 场景 2：AR / VR 交互渲染

**典型 DAG**：姿态感知 → 环境理解 → 场景渲染 → 编码 → 传输 → 显示。帧间形成长链（每帧一个 DAG，帧间还有依赖）。

**任务特点与约束**：
- 时延硬约束："运动到光子"时延需 < 20 ms，否则眩晕
- 计算密集：高分辨率渲染在端上算力不够，必须借助边/云（云渲染/ splits rendering）
- 带宽抖动：无线传输速率波动直接影响帧调度

**对卸载算法的需求**：这是**动态环境下的在线决策**问题——带宽随时波动、任务流持续到达，静态离线调度（HEFT 假设整图已知）不再适用。

**本课题算法适配**：DQN 的思路最匹配（在线、自适应）；本课题实验发现"训练分布外的泛化退化"提示：真实 AR 场景需要 GNN 策略网络与在线微调（见报告改进方向）。E-HEFT 可作为动态环境下的每帧快速基线。

## 场景 3：工业物联网 / 预测性维护

**典型 DAG**：多传感器采集 → 数据清洗 → 特征提取 → 模型推理（异常检测） → 决策/控制指令。宽而浅的扇入结构：多个并行采集支路汇聚到中心分析任务。

**任务特点与约束**：
- 能耗敏感：大量电池供电的传感终端，续航以年计
- 可靠性要求高：控制指令有截止期（deadline），错过即事故
- 周期性任务：每个采样周期执行一遍相同 DAG

**对卸载算法的需求**：**能耗-时延双目标**，且同一 DAG 反复执行，适合离线寻优后固化策略。

**本课题算法适配**：E-HEFT 完全对口——α 就是业务方"续航 vs 实时性"偏好的直接旋钮；α 细扫实验（时延 6.56→4.46 s 换能耗 8.01→14.03 J）演示了如何按场景选 α。DQN 的终局奖励也可加权 λ 以匹配不同产线。

## 场景 4：车联网 / 自动驾驶

**典型 DAG**：多传感器（摄像头/激光雷达/毫米波）感知 → 时空对齐 → 多目标融合 → 轨迹预测 → 路径规划 → 控制制。

**任务特点与约束**：
- 毫秒级硬实时：规划→控制链路超过 100 ms 即不安全
- 任务周期性强且不可拖延：延迟的任务直接作废（不是排队而是丢弃）
- 移动性：车辆与边缘节点的连接持续切换，带宽和时延剧烈变化

**对卸载算法的需求**：安全关键任务必须本地兜底（冗余执行）；可卸载的是非安全关键的增强类任务（高精地图更新、模型 OTA）；算法必须**在线、低决策开销、可容忍链路中断**。

**本课题算法适配**：本课题模型尚无"任务作废/中断"语义，直接套用需扩展——这本身可写进总结的"适用范围"讨论：C-HEFT 适合作为路段级离线预规划参考，DQN 思路适合作为车路协同在线决策的骨架，但需要加入中断与冗余约束。

## 汇总表（可直接放入报告）

| 场景 | DAG 形状 | 主约束 | 关键需求 | 推荐算法 |
|---|---|---|---|---|
| 视频分析 | 深链式 | 时延 + 隐私 | 通信-计算平衡 | C-HEFT / E-HEFT |
| AR/VR | 帧间长链 | <20ms 硬时延 | 在线自适应 | DQN（思路）/ E-HEFT(基线) |
| 工业物联网 | 宽扇入 | 能耗 + 可靠性 | 双目标可调 | E-HEFT（α 按产线调） |
| 车联网 | 多源融合 | 毫秒级硬实时 | 在线 + 冗余 + 低开销 | 需扩展模型后用 DQN |

## 共性结论（回扣实验）

1. **没有一个算法通吃**：静态结构化场景 HEFT 系最优，动态场景 RL 有潜力，能耗敏感场景 E-HEFT 的 α 机制最实用——与实验结论（HEFT 时延最优、E-HEFT/DQN 能耗占优、Pareto 无支配点）一致。
2. **通信代价是绕不开的一等公民**：四个场景的全部瓶颈都出现在"数据产生在端、算力在边/云"的错配上，印证本课题把输入上传/结果回传建模进仿真器的必要性。
3. **动态性是 RL 的主场**：当前实验环境是静态的，DQN 尚未体现压倒性优势；场景 2/4 的带宽波动、任务到达恰是其价值所在——这也是改进方向（动态带宽仿真）的直接动机。
